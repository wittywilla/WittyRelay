Connect a server

How to point a WittyMediaServer at this relay. Apps need nothing: they use it by themselves when a direct connection can't be made.

{{if .Welcome}}

The password is set and you're signed in. Here's how to put the relay to use.

{{end}}

  1. Open the relay's port

    On this machine's firewall, and on the router if it's at home, let these in from the internet:

      {{range .Ports}}{{if .Public}}
    • {{.Port}}/{{.Proto}}: {{.Use}}
      • {{end}}{{end}}

    Ports 8080 and 8081 (health, metrics and this page) stay closed to the internet.

  2. {{if eq .Access "open"}}

    No key needed

    This relay is open: any server may register. Each is still held to the limits on Settings, and only devices a server lists reach it.

    {{else}}

    Give the server owner an access key

    Make one key for each owner, add it to WITTYRELAY_KEYS (comma-separated) and restart the relay:

    docker compose run --rm wittyrelay key

    Keys are passwords: this page never shows them. Take a key out of WITTYRELAY_KEYS to cut that owner off.

    {{end}}

  3. Add the relay on the server

    On the WittyMediaServer: Settings → Remote Access → Peer-to-peer connections → Your own WittyRelay. Paste one of these addresses{{if ne .Access "open"}} and the access key{{end}}, choose Check to read what the relay allows, then Use this relay.

    {{if .Addrs}}
      {{range .Addrs}}
    • {{.}}
      • {{end}}
    {{else}}

    The relay has no address yet. Is it listening? See Health.

    {{end}}

    The address names this machine as the internet reaches it. If it shows a private address (10.…, 172.16–31.…, 192.168.…), set WITTYRELAY_ANNOUNCE to your domain or public IP.

  4. Check it worked

    Within a minute the server shows on Status under Registered servers, with a short ID. It renews its place every five minutes.
